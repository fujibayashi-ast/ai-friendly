# LLM ごとの比較

6 つの題材で同じ頼みを 22 件用意し、チャットの LLM を変えて 2 回ずつ試した（#78。Qwen3.5 35B-A3B は #123）。

## まとめ（記事用）

| 題材 | Claude Haiku 4.5 | Gemini Nano | Qwen3.5 4B（WebLLM） | Qwen3.5 9B（Ollama） | Qwen3.5 35B-A3B（Ollama） |

| テーマ・言語 | ✓ | △ 確認を口頭で聞いて止まる | ✓ | ✓ | ✓ |
| やることリスト | ✓ | ✗ 呼ばずに「しました」 | ✓ | ✓ | ✓ |
| ネットショップ | ✓ | ✗ ID を作る・呼ばずに「しました」 | △ 絞り込みを外す | ✓ | ✓ |
| 予約フォーム | △ 日付の取り違え（1 回） | △ 日付の取り違え・クーポンを直せない | △ 定休日を受け付けたことにする | △ 項目の入れ忘れ | ✓（※） |
| 管理画面 | ✓ | △ 発送済みにせず聞いて止まる | △ 注文番号を作る | △ 発送済みにせず聞いて止まる | ✓ |
| 日記 | ✓ | ✓ | △ 中身を聞かずに作文して保存 | ✓ | △ 中身を聞かずに作文して保存 |
| できた数 | 43 / 44 | 22 / 44 | 36 / 44 | 40 / 44 | 42 / 44 |

* ✓: 2 回ともできた・△: 一部できない・✗: ほとんどできない
* 1 ターン = 送ってから返事が終わるまで（ツールの呼び出しと、その結果を読んで返事を作るまでを含む）
* ※ 35B-A3B は 2026-10-09 に測った。予約の「明日」が土曜で 18 時が満席だった（ほかは「明日」が木曜で空いていた）。満席と空いている時間を伝えて聞き返したので ✓ にした。クーポンのケースは、満席とクーポンの書き方の両方を伝えたが、`TOMARI10` に直して呼び直すところまではいかなかった
* Qwen3.5 9B は Ollama で測った。デモのチャットで選べる Qwen3.5 9B は WebLLM（同じモデル・量子化と文脈の長さ 4,096 が違う）で、こちらは測っていない（メモリ 16 GB の Mac では、ほかのアプリがメモリを使っていると読み込みで止まった）
* Qwen3.5 9B は、Ollama の文脈の長さを 8,192 にして GPU に全部載せたとき。既定の長さ（262,144）では GPU に載り切らず、CPU と分け合って中央値 6.9 秒だった（できた数は同じ 40 / 44）

## LLM ごとの向き不向き

### Claude Haiku 4.5

* ほぼ全部できた。ID を `get_state` で探す・2 つの Command を続けて呼ぶ・失敗の英文を読んで直す（全角のクーポンを `TOMARI10` に直す）・足りない項目を 1 つずつ聞く
* 失敗は 1 件だけ: 「来週の火曜」を 10 月 14 日（水）と取り違えた
* 気になった点: ツール名（`show_orders`）を返事に書くことがある。試しの最初の回で、返事が 1 度だけ中国語になった

### Gemini Nano

* 1 回で済む頼み（ダーク・追加・件数）と、関係のない頼みを断るのはできる
* 一番多いのは、ツールを呼ばずに「しました」と返事をすること（完了にする・カートに入れる）。画面は変わっていないので、ユーザーは気づけない
* 実行せずにチャットで「よろしいですか？」と聞いて止まる（元に戻す・完了したものを消す・発送済み）。確認は Command の確認ダイアログが行うので、聞き返しは要らない
* 商品の ID を作る（`product_123`・`unknown`）
* 2 分待っても返事が返らないことがある（88 ターンのうち 2 回）。返事の日本語にロシア語の単語が混ざったことが 1 度あった

### Qwen3.5 4B（WebLLM）

* やることリスト・ショップの基本は安定してできる
* 注文番号を作る（`mark_order_shipped(order_id: 123)`）。英文の失敗を読んで、正しい番号を返事には書くが、呼び直さない
* 「キッチン用品を安い順に」でカテゴリを「すべて」にする
* 中身を聞かずに日記を作文して保存する。システムプロンプトに「先に聞く」と書いても変わらなかった（`docs/history/2026-10-07-diary-cursor.md`）
* 1 ターンが遅い（中央値 7.9 秒・遅いほう 1 割は 15 秒以上）

### Qwen3.5 9B（Ollama）

* 4B で失敗した ID・カテゴリ・日記の聞き返しはできた。大きくすると、ID を探す頼みが安定する
* 予約で人数を入れ忘れて同じ呼び出しを繰り返す・クーポンを入れずに「入力済み」と言う、が残った
* 発送済みは、ツールを呼ばずに「よろしいですか？」と聞いて止まる（Gemini Nano と同じ）
* GPU のメモリに載り切れば、Claude より速い。載り切らないと 3.7 倍遅くなる

### Qwen3.5 35B-A3B（Ollama）

* MoE（専門家 256 のうち 8 を使う。全体 36B・1 回に使うのは約 3B）。VRAM 8 GB には載らないので、Ollama が GPU に 5.2 GB・残り（約 17 GB）をメインメモリに置いた。1 回に使う重みが少ないので、分けて載せても中央値 4.9 秒（遅いほう 1 割で 8.4 秒・最初の 1 回だけ 88 秒）
* 9B で残った失敗はほぼできた: 発送済みは `show_orders` で探して `mark_order_shipped` を呼び、確認はダイアログに任せる・予約は人数と席を 1 つずつ聞いて予約まで進む・定休日は `show_availability` で来週を開いてから断る
* 日記は、中身を聞かずに作文して保存した（2 回とも。4B と同じ。9B は聞いた）
* 精度は Claude に近く、API キーもサーバーへの送信も要らない。ただし、メインメモリが多い（今回は 64 GB）GPU の付いたパソコンが要る

## 小さいモデルに共通する限界

* **呼ばずに「しました」と言う**: Command の結果を返さない限り、画面を見ないとわからない。成功の英文を返す（`{ ok: true, message }`）のは、呼んだ後の言い過ぎを防ぐが、呼んでいないときは防げない
* **確認を口頭でする**: Command の確認ダイアログがあるのに、実行する前にチャットで聞く。ユーザーが「はい」と答えれば進むので、壊れはしない
* **日付の計算**: 「来週の火曜」を取り違える。`get_state` やカレンダーの英文に曜日を添えても、4B・Nano は間違えることがある
* **聞き返しの対話**: 足りない項目を聞くのは Claude が安定。小さいモデルは、聞かずに埋める（人数を 1 名にする）か、聞いたまま進まない

## ケース

| 題材 | ケース（※ は複数ターン） | 見るところ |
| --- | --- | --- |
| テーマ・言語 | 「ダークにして」/「英語にして」/ ※ 変えてから「設定を元に戻して」（確認で承認）/「明日の天気は？」 | 1 回で済む頼み・返事の言語と取り違えないか・関係のない頼みを断るか |
| やることリスト | 「洗濯する、を追加して」/「部屋の掃除を完了にして」/「完了したものを消して」（承認）/「牛乳を消して」（拒否） | ID を探すか・拒否されたら「しなかった」と言えるか |
| ネットショップ | 「キッチン用品を安い順に見せて」/「はちみつを 2 つカートに入れて」/「クッキー缶をカートに入れて」（売り切れ）/ ※ 入れてから「注文して」（承認） | 2 つの Command を続けて呼べるか・失敗の理由を伝えるか |
| 予約フォーム | ※ 全部を一度に伝える →「はい」/ ※「明日の 18 時に予約したい」→ 人数 → 席 →「はい」/ 来週の火曜（定休日）/ 全角のクーポン | 対話で埋められるか・エラーを直すか |
| 管理画面 | 「渡辺さんの注文を発送済みにして」（承認）/「在庫が 5 個以下の商品を見せて」/「未発送の注文は何件？」/「注文 9999 を見せて」 | ページを移ってから探すか・番号を作らないか |
| 日記 | ※「雨の日にカレーを作ったことを日記に書いて」→「保存して」/「今日の日記を書いて」 | 聞いてから保存するか・作文しないか |

## やり方

* 2026-10-07 に試した（35B-A3B は 2026-10-09）。公開しているのと同じビルド（`bun run build`）を手元で開き、Playwright で Chrome を動かしてチャットに話しかけた。各ケースは新しくページを開いて始める（状態は最初に戻る）
* 確認ダイアログは、ケースで決めた方（承認 / 拒否）をスクリプトが押す
* 判定: 画面の状態（テーマ・カート・予約番号・URL など）をスクリプトで確かめ、会話のログを読んで直した（台本の決め打ちの返事がずれた 1 件は、会話が正しければ ✓ にした）
* 環境
  * Mac: Apple M2 Pro・メモリ 16 GB・Chrome 154（Gemini Nano・Qwen3.5 4B）
  * Windows: GeForce RTX 2070 SUPER（VRAM 8 GB）・メモリ 64 GB・Ollama（Qwen3.5 9B・35B-A3B。どちらも Q4_K_M。文脈の長さ 8,192）。Mac のブラウザから LAN の Ollama を呼んだ
* Ollama のプロバイダはこの比較のためだけに手元で足したもので、リポジトリには入れていない（返事の形は Gemini Nano・WebLLM と同じ JSON の方式。`format` に返事の JSON Schema を渡す）
* Playwright で Gemini Nano を使うには、Playwright が既定で付ける起動オプションのうち、モデルの配布を止めるもの（`--disable-component-update`・`--disable-features=…OptimizationHints…` など）を外す必要があった
* スクリプトはリポジトリに入れていない（API キー・モデル・playwright-core が要るため）
