## このサイトで見せること

settings・やることリストにないものを選んだ。

* AI が画面の表示を変える（`set_category`・`sort_products`）。これまでの Command はデータを変えるもの（追加・削除・設定）だけだった
* 数量と金額。`add_to_cart(product_id, quantity)` の数は、カートの分と合わせて在庫まで
* 商品の状態（売り切れ・発売前・在庫の上限）による失敗を、AI が読んで直せる英文で返す
* 非同期の Command。`place_order` はダミーの API（通信しない）を待つ
* 金額の入った確認。`confirmation`（#58）で今のカートから「合計 ￥3,480 の注文を確定します。」を作る

## 決めたこと

* 絞り込みは最初は外す案だった（やることリストでは外した）が、「AI が表示を変える」を見せるため、絞り込みと並べ替えを画面と AI の両方に置いた
* 商品の状態は、在庫数と発売日をデータに持たせて決める。発売前かは発売日があるかで決め、今日の日付とは比べない（日がたっても表示が変わらないように）
* 在庫は表示とカートの上限だけを扱い、入荷などの管理はしない。注文すると在庫が減り、最後の 1 点を買うと売り切れになる
* サイトの関数（`shop.ts`）は、売り切れや在庫を超える数を黙ってそろえる（画面ではそもそも押せない）。Command は呼ぶ前に確かめ、そろえずに理由を返す。黙ってそろえると、AI は「2 つ入れた」と思ったまま返事をしてしまう
* `get_state` の商品は、絞り込みに関係なく全部返す。表示と AI が探せる範囲を分ける
* 商品名は ja / en の両方で持ち、表示中の言語で出す（やることリストの名前はユーザーのデータなので訳さないが、商品はお店が用意するデータ）
* 写真は使わない（外部の画像を読まない・素材を持たない）。カテゴリのアイコンを置く

## 本物の Qwen3.5 4B で試した

| 頼み | 結果 |
| --- | --- |
| はちみつを 2 つカートに入れて | `get_state()` → `add_to_cart(product_id: "6", quantity: 2)` |
| キッチン用品を安い順に見せて | `set_category(category: "kitchen")` → `sort_products(order: "price_asc")` |
| クッキー缶をカートに入れて（売り切れ） | `get_state()` だけで、入れずに「在庫切れのため入れられません」 |
| 万年筆を買いたい（発売前） | `get_state()` だけで、発売日を添えて「まだ発売されていないため購入できません」 |
| はちみつを 1 つ減らして | `set_cart_quantity(product_id: "6", quantity: 1)` |
| マグカップも 1 つ入れて | `add_to_cart(product_id: "2", quantity: 1)` |
| 注文して | `get_state()` → `place_order()`（確認ダイアログを経て） |
| 今日の天気は？ | ツールを呼ばずに断った |

* 売り切れ・発売前は、`get_state` の `status` を見て、Command を呼ぶ前に断った（システムプロンプトの「入れずに伝える」どおり）
* 1 回 13〜37 秒（注文は確認ダイアログとダミーの API の待ちを含む）。同じマシンで開発サーバーを複数動かしていたので、やることリストより遅め
