# 2026-10-07 管理画面（ページ遷移を Command にする）

#73（サブ Issue #87・#88・#89）で決めたこと。仕様は [apps/admin/docs/commands.md](../../apps/admin/docs/commands.md)。

## きっかけ

* 運用の管理画面は機能が多く、設定がいくつもの画面に散らばっていて、どこで何をすればいいかわからないことが多い。AI に頼めば操作できる、はこのプロジェクトの使いどころとして伝わりやすい
* これまでの題材は 1 ページだった。ページ遷移も Command にする題材として作る（表はシンプルにし、遷移を主役にする）

## 決めたこと

* ルーターは React Router（宣言的な書き方）。一番使われていて、読者の手元のサイトに当てはめやすい
* 絞り込みは URL の検索条件に入れる。URL を作る関数（`routes/paths.ts`）を、画面のリンク・絞り込みとページ遷移の Command が共有する（画面と AI で同じ関数）
* Command は、どのページにいても全部使える。遷移はユーザーに画面を見せるためと、見えている行を読むため
* `get_state` は今のページと、画面に見えている行だけ（予約フォームの「見えている週だけ」と同じ）。探すときは、ページを開いてから読む
* 画面は注文と商品・在庫だけ（会員・キャンペーンは作らない）
* データはルーターより上の Provider に持ち、どのページからも同じ関数（`markShipped`・`setStock`）を呼ぶ。だめな理由はサイトの関数が返す（[2026-10-07-guards-in-site.md](2026-10-07-guards-in-site.md)）

## 比べた案

| 案 | 採らなかった理由 |
| --- | --- |
| TanStack Router | 型安全だが、読者の母数は React Router より少ない |
| ルーターを使わない（history API と state） | 依存は増えないが、普通のサイトの見本として不自然 |
| ページごとに Command を変える（今のページの操作と遷移だけ出す） | WebMCP のページごとの登録に近く、小さいモデルに見せるツールも減る。今回は、どのページからでも頼める方を選んだ |
| ページ遷移の結果は件数だけ返し、行は `get_state` で読ませる | Qwen は `get_state` を読まずに注文番号を作った（`order_id: "1"`）。「read get_state」と英文に書くと、返事に「get_state で確認できます」と出した |

## ページ遷移の結果に、見えているものを短く返す

* `show_orders` は `1026 渡辺 翔 (pending)`、`show_products` は `6 はちみつ (stock 2)`、`show_order` は商品と合計を返す
* #77 では「一覧などのデータは返さない（読むものは `get_state`）」とした。ページ遷移は「開いた」ことが結果で、何が見えているかはその一部なので、番号・名前・状態だけを短く返すことにした。全部の項目は今までどおり `get_state`
* 商品の要約に名前がないと、Qwen は「はちみつ」の ID が分からず `product_id: "hachimitsu"` を作った

## 注文番号・商品 ID を数値にする

* Qwen3.5 4B（WebLLM）は、`"order_id": "1029"` のような数字だけの文字列を書く途中で、出力が `"order_id":   "}]}` で止まり JSON が壊れた（`finish_reason: "stop"`。`temperature: 0` なので毎回）。JSON Schema で形を縛っているので WebLLM 側の不具合と思われる（#93）
* 注文番号はもともと数値なので、サイトのデータでも数値で持つことにした（AI のために Command だけで変換するのではなく）。商品 ID も同じにそろえた

## Qwen3.5 4B での結果

| 話しかけ方 | 結果 |
| --- | --- |
| 「渡辺さんの注文を発送済みにして」→「未発送のものです」 | `show_orders(query: 渡辺)` で 3 件（1026 が未発送）と答え、`mark_order_shipped(1026)` → 確認ダイアログ → 発送済み |
| 「小林さんの未発送の注文を全部発送済みにして」→「はい」 | `show_orders(status: pending, query: 小林)` → 2 件を続けて発送済み（確認ダイアログが 2 回） |
| 「在庫が 5 個以下の商品を見せて」→「はちみつの在庫を 10 にして」 | 6 件を名前と在庫つきで答え、`set_stock(6, 10)` |
| 「オリーブオイルの在庫を 20 にして」（注文一覧から） | `get_state` → `show_products` → `set_stock(12, 20)` |
| 「注文 1029 の中身を教えて」 | `show_order(1029)` で開き、「山本 結衣様からの万年筆 x2、合計 11,600 円」 |
| 「未発送の注文は何件？」 | `show_orders(status: pending)` で 9 件 |

* 「渡辺さん」の「さん」は付けずに探せた（システムプロンプトに書いた）
* Claude は API キーが要るため、この PR では試していない（#78 で全サイトをまとめて試す）
