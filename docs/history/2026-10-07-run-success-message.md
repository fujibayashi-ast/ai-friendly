# 2026-10-07 成功したときにも AI 向けの英文を返す

#77 で決めたこと。仕様は [docs/commands.md](../commands.md) の `run` と「結果とエラー」。

## きっかけ

* 予約フォーム（#46）を Qwen3.5 4B で試すと、`fill_reservation_form` の `{ ok: true }` だけを見て「予約が完了しました」と返事をした（まだ送っていない）。足りない項目を聞き返す対話もできなかった（[2026-10-06-reservation-app.md](2026-10-06-reservation-app.md)）
* 成功の結果が `{ ok: true }` だけでは、「入れたがまだ送っていない」「人数と席がまだ」のような、次の一手に要ることを AI に渡せない

## 決めたこと

* `run` は成功のときに `{ ok: true, message }` を返してよい。ツールの結果は `{ ok: true, message: "<type>: ..." }`（失敗と同じく前に `<type>: ` を付ける）。何も返さない Command はこれまでどおり `{ ok: true }`
* 予約フォームで使う
  * `fill_reservation_form`: `filled in; not sent yet. still missing: party_size, seat (ask the user for them one at a time)` / `… all fields are filled; ask the user whether to book it`
  * `submit_reservation`: サイトの `submit()` が受け付けた予約番号を返し、Command が `reservation 1001 was made for …` にする
* 足りない項目は、画面にも「予約する」の横に出す（「あと時刻、人数、席を入れると予約できます。」）。AI のためだけでなく人にもわかりやすく、画面と Command が同じ `missingFields` を使う（[画面と AI は同じ関数](2026-10-06-reservation-app.md)）
* ほかの題材には足さない（`{ ok: true }` で困っていない。ネットショップの注文番号も同じ形でできる）

## 比べた案

| 案 | 採らなかった理由 |
| --- | --- |
| システムプロンプトに「入れただけでは送っていない」と書き足す | 小さいモデルは長いプロンプトの中の 1 行を守りにくい。結果に書けば、そのツールを呼んだ直後に読む |
| 成功の結果に今のフォームの値を丸ごと返す | 読むものは `get_state` に分けている。返すのは次の一手に要る短い英文だけにする |
| 全部埋まったときの英文で `call submit_reservation only if the user wants to book` とツール名を書く | Qwen が返事にそのまま「submit_reservation を使用してください」と書いた。ツール名を出さず「予約してよいか聞く」にした |
