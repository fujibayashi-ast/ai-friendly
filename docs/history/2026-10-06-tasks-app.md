## Command

* settings サイトでは見せられなかった「ID のある物を探して操作する」を見せる。AI は `get_state` で名前から ID を探してから操作する
* ID は `"1"` のような短い連番にした（小さいモデルでも扱いやすい）。存在しない ID は今ある ID を添えた英文で返す
* 削除の確認は AI からだけにした。画面からの削除は普通の TODO アプリと同じく確認しない。確認の要否は Command の定義に持つので、人の操作には関係しない
* 「完了したものを消して」で `delete_task` を 1 つずつ呼ぶと確認がその数だけ出るため、`clear_completed` を用意した。確認は条件付き（完了したものがあるときだけ）にし、なければ確認せずに失敗を返す
* 比べた案: `clear_completed` を作らず、AI に `get_state` で完了したものを探させ、`delete_task` を何回も呼ばせる
  * 採らなかった理由: 確認ダイアログが件数分出る（1 回頼んだのに何回も承認する）。小さいモデルは取りこぼしや途中で止まることがある
  * 既存の Command を AI が組み合わせる形は、「牛乳と掃除を消して」のような個別の頼みで見せられる。まとめた操作を Command として用意する形と、1 つのサイトで並べて比べられる
* トップのカードの例は、言語を切り替えても値が変わらない `clear_completed()` にした（`add_task(title: "牛乳を買う")` だと英語表示で合わない）

## 画面は最小限にし、「完了したものを削除」は AI からだけ

* レビューで、絞り込み（すべて・未完了・完了）・未完了の件数・「完了したものを削除」のボタンは要らないとなった。画面は追加・完了のチェック・削除だけにした
* 「完了したものを削除」は画面に置かず、AI からだけ使える `clear_completed` にした（settings の `reset_settings` と同じ見せ方）。サイトに専用の関数は作らず、Command がサイトの `deleteTask` を完了したものの数だけ呼ぶ。サイトにない機能でも、サイトの関数を組み合わせて AI に足せることを見せる
