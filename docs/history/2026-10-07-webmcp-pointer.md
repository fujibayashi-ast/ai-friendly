# 2026-10-07 WebMCP から呼んでも、チャットと同じ動き（カーソル）にする

#119 で決めたこと。仕様は [docs/assistant.md](../assistant.md) の「AI の操作を見せるカーソル」と [docs/ai-tools.md](../ai-tools.md)。

## きっかけ

* 公開先で WebMCP が使えるようになった（#117）。日記を WebMCP から操作すると、ページ遷移・入力が数 ms で終わり、一覧に戻った最後の画面しか見えなかった
* チャットと WebMCP には同じツールを渡しているが、チャットは `execute(input, { pointer })`、WebMCP は `execute(input)` で、`pointer` だけが違った（日記を作ったときに「WebMCP では動かない」と決めていた。[2026-10-07-diary-cursor.md](2026-10-07-diary-cursor.md)）
* WebMCP では、ユーザーはサイトのチャットを見ていない。操作を見せる価値はチャットより大きい

## 決めたこと

* `registerWebMcpTools` に `pointer` を渡せるようにし、日記はチャットと同じカーソルを渡す。`command` には型を受け取る口だけを足し、カーソルの演出は `assistant` に置いたまま
* WebMCP にはチャットの「返事の終わり」がないので、`assistant` に `webMcpPointer` を置く。押す・打ち込むが終わってから 2 秒操作がなければカーソルを隠す
* 渡すのは日記だけ。ほかの題材の Command は `pointer` を使わないので、チャットでも WebMCP でも同じ（管理画面のページ遷移も、どちらからでも一瞬で移る）
* 打ち込みの間、下書きが変わるたびにツールが作り直され、WebMCP の登録が解除・再登録される（試したときは 168 回）。解除された実行中のツールでも、Chrome は結果をエージェントに返したので、登録のしかたは変えない

## 比べた案

| 案 | 採らなかった理由 |
| --- | --- |
| `createAiTools` で `pointer` を決め、チャット・WebMCP のどちらから呼んでも同じにする | チャットは今も実行のときに `pointer` を渡している。作るときと実行するときの 2 か所で決められると、どちらが効くかがわかりにくい |
| `command` の既定の `pointer` をカーソルにする | `command` に DOM の演出が入る（日記のときと同じ理由） |
| 実行中は WebMCP の登録をし直さない | 試したら、登録し直しても結果は返った。要らない |
| カーソルを隠さない | 最後に押した位置に出たままになる |
| ツールの実行が終わるたびにすぐ隠す | エージェントは `fill_entry` → `save_entry` と続けて呼ぶので、間で毎回消える。少し待つ |
| すべての題材で `webMcpPointer` を渡す | 今は動きが変わらない。最小限にする |
