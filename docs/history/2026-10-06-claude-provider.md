# 2026-10-06 Claude API のプロバイダ

#27 で決めたこと。仕様は [docs/assistant.md](../assistant.md) の「プロバイダ」。

## Claude API を先にした

* 候補は Claude API・Chrome の Prompt API（Gemini Nano）・WebLLM（Qwen 4B 級）の 3 つ
* 最小限にするため 1 つずつ作ることにし、確実にツールを呼べて、`fetch` だけで作れる Claude API を先にした
* ローカル LLM と、チャットの入力欄での Claude / ローカル LLM の切り替え（Claude のチャット欄のモデルの選択のような形）は #29 に分けた。選択肢が 1 つの間は切り替えを出さない
* モデルは Haiku 4.5 に固定した。設定を変えるくらいなら十分で、速く安い

## ブラウザから直接呼ぶ

* サーバーを置かない方針のため、ブラウザから Claude API を直接呼ぶ（`anthropic-dangerous-direct-browser-access: true`）
* 利用者自身の API キーを使う前提。キーはコードに含めず、settings サイトは state に持つだけで保存しない（再読み込みで消える。サンプルとして最小限にするため、sessionStorage への保存はやめた）
* CLAUDE.md の「LLM はローカルのみ・外部通信なし」に、「利用者がキーを入れて話しかけたときだけ Claude API に通信する」を例外として足した
* SDK（`@anthropic-ai/sdk`）は使わず `fetch` にした。使うのはメッセージの送信だけで、依存を増やすほどではない

## 仮のボットを外した

* #11 で作った仮のボット（決まった言い回しで動く）は、本物の LLM をつないだら外すと決めていた（本題ではないため）
* テスト用に残す案もあったが、会話のループのテストは自前の偽のプロバイダで足りるので、まるごと外した

## チャットの中で確認する（#10）を見送った

* AI が確認の要る Command を実行するとき、チャットの中のボタンで確認する案（#10）は、使い心地の工夫で本題ではないため見送った
* 確認はサイトの確認ダイアログ（`useConfirm`）1 か所で行い、チャットからも WebMCP からも同じ確認になる。チャットの中で確認すると、チャットを通らない WebMCP からの操作の確認が別に要る

## 実装中に決めたこと

* AI の返事は、Claude が書いた順に「文 → ツールの行」で出す（仮のボットは文がなかったので逆にしていた）
* 返事を受け取れなかったターンの後は user が続くので、Claude に送るときに 1 つにまとめる
* キーを保存した・「キーを変更」を押した、で入力欄が入れ替わるので、新しい入力欄にフォーカスを移す
