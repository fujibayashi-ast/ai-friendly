# 2026-10-06 Command 基盤から Undo / Redo と操作の履歴を外す

#21 で決めたこと。最初の設計（Undo をスナップショット方式にした理由など）は [2026-10-05-command-core.md](2026-10-05-command-core.md)。

## 外した理由

* このプロジェクトで見せたいのは「AI が少ない手数でサイトを操作できる」こと。その支えは次の 3 つで、Undo がなくても成り立つ
  * バッチ（1 つでも失敗したら何も適用しない）
  * LLM が読んで自分で直せる英文のエラー
  * 危ない操作の前の確認フック
* 「普通のサイトに足す」形（#19 の `store`）にすると、画面の操作は Command を通らない。Undo を残すと「AI のバッチの後に人が変えていたら戻してよいか」の判定（状態の比較）などが要り、プラスアルファの機能のために基盤が複雑になる
* 参考にしている loop-study も、戻す操作は入れていない

## 外したもの・残したもの

* 外した: `undo` / `redo` / `canUndo` / `canRedo` / `getHistory`、`nothing_to_undo` / `nothing_to_redo`、`HistoryEntry`
* 残した: 発行元（`source`）。確認フックを AI の操作だけに効かせるのに使う
* 戻したいときは、AI が状態を読んで、戻すための Command を新しく実行すればよい

## チャット（#11）への影響

* #13 のレビューで #11 に追記した「チャットから Undo / Redo を頼む」「操作の記録をダイアログで出す」は取り下げる
* AI が何をしたかを見せたいときは、チャットが自分の会話のログとして持てばよい

## 採らなかった案

* **Undo を残し、外での変更を検出して止める**: PR #20 で一度入れた（中身の比較で `state_changed` を返す）。動くが、メインではない機能のために基盤とライブラリ（dequal）が増えるのでやめた
* **人の操作も Undo できるようにする**: 要るのは編集アプリのような Command 前提のサイト。そういうサイトを作れる人なら、記事から AI 側へすぐ転用できる
