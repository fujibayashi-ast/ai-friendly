# 2026-10-06 予約フォーム（apps/reservation）

#46 で決めたこと。仕様は [apps/reservation/docs/commands.md](../../apps/reservation/docs/commands.md)。

## 分け方

* ほかの題材と同じく、#74（サイトの土台）→ #75（画面。普通のサイトとして）→ #76（Command と AI の層）の stacked PR にした

## このサイトで見せること

* AI がフォームを埋める。画面の入力欄が会話に合わせて埋まり、ユーザーは確かめてから送る
* 入力のエラーを AI が読んで直す。定休日・満席・席と人数・クーポンコードの形（半角・全角や大文字・小文字は、人が入力に困りやすいところ）
* 今日の日付を AI に渡す（「明日」「来週」を日付に直すため）
* AI 用の特別な Command を作らない。どの Command も画面の操作と同じサイトの関数を呼ぶ

## 決めたこと

* Command は 3 つ（`fill_reservation_form`・`show_availability`・`submit_reservation`）
  * 入力欄ごとに Command を分ける案もあった（入力欄と 1 対 1 で一番素直）。小さいモデルに渡すツールの一覧が長くなり、1 つの頼みで何回も呼ぶことになるので、まとめた。入力は React Hook Form の `setValue` で入るので、Command はそれを項目ぶん呼ぶ `fill(patch)` を包むだけ。人は入力欄から 1 項目ずつ、AI はまとめて、同じ React Hook Form のフォームに入れる
  * 「入力をクリア」は画面にないので Command も作らない（入れ直すときは上書きする）
* 空き状況は、`get_state` にカレンダーに出ている週だけを入れる。最初は 4 週間分を入れる案だったが、画面に見えていない情報を AI にだけ渡すことになるのでやめた。ほかの週は、AI も人と同じく週を送ってから読む（ユーザーは週をめくらずに AI に聞ける）
* 空き状況を返す Command（読むためのツール）は作らない。Command は成功で `{ ok: true }` しか返せないので、読むものは `get_state` にそろえた
* `fill_reservation_form` は、入れた値にエラーがあっても値は残して、失敗としてエラーを返す。人が入力したときに入力欄の下にエラーが出るのと同じで、AI もその場で直せる
* サイトは入力を黙って直さない（全角を半角にするなど）。直すのは AI の役目にして、普通のフォームと同じエラーを出す
* フォームは React Hook Form と zod（`zodResolver`）で書く（レビューで変えた）
  * 最初は自前の state と `updateForm(patch)`・`validate` で書いていた。実際の React のフォームは React Hook Form と zod で書かれていることが多く、自前の形だと「このサンプル用に作りやすくした」と見えるおそれがある。よくある書き方のフォームに、`setValue` を通して AI の層を足せることを見せる
  * エラーを出す時機（変えた欄はその場で、空の欄は送るとき）・送信中（`isSubmitting`）・受け付けの表示を消す時機（`isDirty`）は React Hook Form に任せた
  * ルールは zod の `superRefine` に書き、エラーの `message` をエラーの種類（`closed` など）にした。画面は文言に、Command は英文にする
* `submit_reservation` は、画面の「予約する」と同じ `submit()`（`handleSubmit`）を呼び、サイトが返す結果（成功・送信中・入力のエラー）を英文にする（レビューで変えた）
  * 最初は Command の中で入力を確かめ、エラーがあれば画面にエラーを出すためだけに `submit()` を呼んでいた。AI の送信が画面の送信と同じ処理を通らず、`run` も長かった
  * `fill_reservation_form` は画面に同じ操作（まとめて入れる）がないので、エラーは Command の中で作る（`fill` は何も返さない画面の関数のまま）。React Hook Form の検証は次の描画で反映されるので、入れた値で同じルール（`formErrors`）を確かめる
* 日付の計算は dayjs で行う。手で書くと時差のずれを避ける小細工が要り、読み手が引っかかりやすい。表示は `Intl`
* 名前・電話番号は聞かない（個人情報を扱わない）

## 本物の Qwen3.5 4B で試した

| 頼み | 結果 |
| --- | --- |
| 明日の 19 時に 2 名、テーブルで予約したい | `get_state()` → `fill_reservation_form(date: "2026-10-07", time: "19:00", party_size: 2, seat: "table")`。ただし送る前に「予約が完了しました」と返事をした |
| （続けて）予約して | `submit_reservation()`（確認ダイアログを経て送れた） |
| 来週の火曜に 2 名で予約したい | 「来週の火曜日は閉店しています」。React Hook Form に変えた後にもう一度試すと、来週の火曜を 10 月 14 日（水曜）と取り違えて「予約は可能です」と答えた（曜日から日付を出すのも安定しない） |
| クーポン ｔｏｍａｒｉ１０ を使いたい | `fill_reservation_form(coupon_code: "tomari10")` → 形のエラー → `coupon_code: "TOMARI10"` に直して入れた |
| 来週の空いている日は？ | `show_availability(week_of: "2026-10-13")` の後に `get_state` を読まず、「まだ確認できていません」 |
| 明日の 19 時に予約したい →「2 人です」→「テーブルで」 | 人数を聞き返さず「予約を完了しました」。「2 人です」で同じ入力を 5 回繰り返して止まった |

* 一度に全部伝えると入れられるが、足りない項目を聞き返す対話（「何名ですか？」）はできなかった。入れた直後に「完了しました」と言うことも多い
* 最初は今日の日付を `get_state` にだけ入れていたが、Qwen は読まずに 2024 年の日付を作った。システムプロンプトにも今日を書くと、正しい週を指定した
* 確認ダイアログがあるので、聞き返さずに送ろうとしても、ユーザーの承認なしには送られない
