# ハーネスの効果

[llm-comparison.md](llm-comparison.md) は、どの LLM もすべて同じハーネス（Command・引数の検証・確認・英文のエラー・`get_state`）で試したもので、LLM どうしの差しかわからない。ここでは、同じ LLM・同じ 22 件で、ハーネスを替えたり部品を外したりして、何が効いているかを確かめた（#129）。

* A: ツールを Command（サイトの関数）から、汎用の DOM 操作（画面を読む・押す・入れる）に替えた
* B: ハーネスの部品（英文のエラー・`get_state`）を 1 つずつ外した
* LLM は Claude Haiku 4.5 と Qwen3.5 35B-A3B（Ollama）。それぞれ 2 回ずつ

## まとめ

| | Claude Command | Claude DOM | 35B Command | 35B DOM |
| --- | --- | --- | --- | --- |
| できた数 | 44 / 44 | 37 / 44 | 42 / 44 | 32 / 44 |
| 1 ターンの返事（中央値） | 2.9 秒 | 4.9 秒 | 4.9 秒 | 8.2 秒 |
| 1 ケースのツールの呼び出し（平均） | 1.5 回 | 4.2 回 | 1.8 回 | 4.0 回 |
| 確認なしで実行した操作 | 0 | 10 | 0 | 10 |

* DOM 操作でも、1 回で済む頼み・フォームの入力・ページの移動はおおむねできる。ただしツールの呼び出しが 2〜3 倍になり、返事も遅くなる
* DOM 操作では、確認ダイアログを通らない。Command なら確認が出る 5 ケース（設定のリセット・完了したものの削除・牛乳の削除・注文・発送済み）を、2 つの LLM とも 2 回とも確認なしで実行した。「牛乳を消して」は確認で拒否する台本だったが、画面の削除ボタンをそのまま押して消した
* 部品を外すと、はっきり落ちる。`get_state` を外すと、名前から ID を探す頼みが 12 件中 2 件しかできない（Claude は ID をユーザーに聞き、35B は ID を作る）。英文のエラーを外すと、全角のクーポンを 2 つの LLM とも直せない

* 「（確認なし）」は、Command なら確認ダイアログが出る操作を、確認なしで実行したもの（頼みどおりにはできているので ✓ にしている）
* 「英語にして」は、DOM 版のシステムプロンプトが汎用のもの（サイトの説明がない）なので、サイトの言語の切り替えだと思わず断った。Command 版のプロンプトには「『英語にして』はサイトのこと」と書いてある。ツールの差ではなく、プロンプトの差
* 「安い順に」は、並べ替えの選択肢（shadcn の Select）を開いて選ぶ手数が要る。Claude は 1 回、並べ替えていないのに「安い順に表示できました」と返した。35B は絞り込みだけして、並べ替えはユーザーに頼んだ
* 管理画面の件数・在庫は、35B が画面の表を読んで数え間違えた（未発送を 10 件・在庫 0 のクッキー缶を抜かした）。Command 版は、絞り込んだ一覧の件数を受け取る
* 「今日の日記を書いて」は、Claude の DOM 版が中身を聞かずに作文して保存した（Command 版は聞いた）。35B の DOM 版は、ユーザーに「書く」を押すよう頼んで止まった

## B: 部品を外した比較

| 外したもの | ケース | Claude（外す前） | Claude（外した） | 35B（外す前） | 35B（外した） |
| --- | --- | --- | --- | --- | --- |
| 英文のエラー | 全角のクーポン | ✓ | ✗ | ✓ | ✗ |
|  | 来週の火曜（定休日） | ✓ | △ | ✓ | ✓ |
|  | 「クッキー缶をカートに入れて」（売り切れ） | ✓ | ✓ | ✓ | ✓ |
|  | 「注文 9999 を見せて」 | ✓ | ✓ | ✓ | ✓ |
|  | 「はちみつを 2 つカートに入れて」 | ✓ | ✓ | ✓ | ✓ |
| | できた数 | 10 / 10 | 7 / 10 | 10 / 10 | 8 / 10 |
| `get_state` | 「部屋の掃除を完了にして」 | ✓ | ✗ | ✓ | ✗ |
|  | 「牛乳を消して」（確認で拒否） | ✓ | ✗ | ✓ | ✗ |
|  | 「はちみつを 2 つカートに入れて」 | ✓ | ✗ | ✓ | ✗ |
|  | 「クッキー缶をカートに入れて」（売り切れ） | ✓ | ✗ | ✓ | ✗ |
|  | 入れてから「注文して」（確認で承認） | ✓ | ✗ | ✓ | ✗ |
|  | 「渡辺さんの注文を発送済みにして」（確認で承認） | ✓ | ✓ | ✓ | ✓ |
| | できた数 | 12 / 12 | 2 / 12 | 12 / 12 | 2 / 12 |

* 「外す前」は A の Command 版の結果
* 英文のエラーを外す: 失敗は `{ ok: false, message: "failed" }` だけを返す。全角のクーポンは、Claude はユーザーに形式を聞き返し、35B は「予約できませんでした」と返した（外す前は、英文のエラーを読んで `TOMARI10` に直した）。定休日・売り切れ・ない注文は、`get_state` やページを移る Command の結果（カレンダー・商品の状態）から読み取れるので、外しても大きくは落ちない（Claude の定休日の 1 回は、10 月 14 日を火曜と取り違えたもの）
* `get_state` を外す: システムプロンプトの `get_state` に触れた文も外した。Claude は「ID を教えてください」とユーザーに聞き、35B は ID を作った（`room_cleaning`・`honey_001`・`milk`）。発送済みは、`show_orders` が開いた一覧の注文を返すので、外しても落ちない

## わかったこと

* サイトの関数を Command として渡すと、DOM 操作よりツールの呼び出しが少なく（半分以下）、速く、確認を必ず通せる。DOM 操作でも多くの頼みはこなせるが、確認ダイアログのような守りはサイトの画面にない限り効かない
* ハーネスの部品のうち、`get_state`（AI が ID を探すための状態）が一番効いている。外すと、名前で頼む操作のほとんどができなくなる
* 英文のエラーは、入力のルールのように、AI がほかから知りようのないことを伝えるときに効く（全角のクーポン）

## やり方

* 2026-10-09 に試した。#78 と同じ 22 件・同じスクリプト（Playwright でチャットに話しかける）・同じ判定（画面の状態 + 会話のログ）
* 試すためのコード（DOM 操作のツール・部品を外すしくみ・Ollama のプロバイダ）は手元だけで、リポジトリには入れていない
  * DOM 操作のツール: `read_page`（画面の文字と、押せる・入れられる要素を番号付きで返す。チャットは除く）・`click(ref)`（pointer / mouse のイベントを順に送ってから `click()`）・`fill(ref, value)`（React が拾えるように値を入れて `input` / `change` を送る）
  * DOM 版のシステムプロンプト: `read_page` で見て、番号で押す・入れる・結果を確かめてから返事をする・今日の日付・関係のない頼みは断る
* チャットの上限（1 回の頼みで LLM を呼ぶのは 5 往復まで）は、DOM 操作だと普通の頼みでも超えるので、どの方式も 15 往復に上げてそろえた。本物のサイトの 5 往復のままなら、DOM 版はもっと落ちる
* 35B の Command 版は、同じ日に測った #123 の結果（上限 5 往復のまま。一度も上限に当たっていない）
* 予約は「明日」が満席の土曜だった（#78 の日は空いていた）。Claude の Command 版もこの日に取り直したので、表の中では条件がそろっている。満席と空いている時間を伝えて聞き返したら ✓ にした
* DOM 版では、AI が並べ替え・時刻の選択肢を開いたままにすると、チャットが閉じたり入力できなくなったりした。スクリプトで、発言の前に選択肢を閉じ（Escape）、チャットを開き直した（人が外を押すのと同じ）
* 各ケースの終わりの画面はキャプチャを撮って手元に残した（リポジトリには入れていない）
